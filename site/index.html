Know which local LLMs will run on your machine

local-llmup scores your hardware, then gives every model a straight answer — yes, slow, or no, with an estimated tokens-per-second range — before you download a thing. Then it pulls, serves, and migrates memory, all locally.

Get started View on npm
npm install -g local-llmup

10 commands - yes/slow/no verdicts - est. tok/s - local-first workflow

Runnability, not guesswork

An AI Hardware Score (0–100) names your bottleneck, and every model gets a yes / slow / no verdict with an estimated tok/s range. Size the KV cache at a chosen window with recommend --context, or find each model's ceiling with --max-context. Unknown hardware or geometry says “unknown” — never a made-up number.

One-command lifecycle

`up`, `down`, `switch`, and `doctor` coordinate the local server lifecycle through Ollama with safer defaults and consistent diagnostics.

Portable memory switching

Migrate local memory from one model to another when you change quality or latency targets, while keeping conversational continuity.

Get running in a few commands

Use the defaults for quick setup, then switch to a specific model when ready. These are examples from a typical local workflow.

Install and rank

npx local-llmup

Prints ranked models with a verdict and est. tok/s, plus a top-pick command.

Will it run?

local-llmup can-run llama3.1:8b

Answers yes / slow / no with est. tok/s. Exits non-zero only for no, so it scripts.

Size the context

local-llmup recommend --context 32768

Re-ranks with the KV cache sized at your window. Add --max-context for each model's ceiling.

Pull and serve

local-llmup up qwen3:30b-a3b

Pulls the model through Ollama and brings up the local server endpoint.

Chat

local-llmup chat -m qwen3:30b-a3b

Starts an interactive prompt against your active or selected model.

Diagnostics

local-llmup doctor

Scores your hardware, names the primary bottleneck, and reports actionable issues.

All commands

Ten commands cover the whole local-LLM lifecycle — from hardware-aware discovery to serving, chatting, and migrating memory. Run any command with --help, or --json for machine-readable output.

Command What it does
recommend Default command. Ranks the catalog for your machine with a yes / slow / no verdict and est. tok/s. Size the KV cache with --context or find each model's ceiling with --max-context; filter by --task.
can-run Checks a single model and answers yes / slow / no with the binding reason and est. tok/s. Exits non-zero only on no, so it works as a script gate.
catalog Lists the curated model catalog with quantization, size, and context length. Filters to what fits your machine.
doctor Scores your hardware (0–100), names the primary bottleneck, and reports actionable environment issues.
up Pulls a model through Ollama (integrity-verified) and brings up the loopback-only server endpoint.
chat Opens an interactive prompt against the active or selected model; the exchange is recorded to local memory.
ls Shows the currently active model and server endpoint.
switch Switches the active server to a different already-served model.
migrate Moves local memory from one model to another when you change quality or latency targets. Preview with --dry-run.
down Stops the local server when you are done.
